# PMP progress: a Codex → Antigravity → Codex round trip through MCP

November 14, 2026 — experimental local case study

We kept building PMP beyond the initial bridge. This week we completed a bounded task handoff between Codex and Antigravity through a shared local MCP mailbox, including the return trip.

The practical problem was straightforward: moving work between agent applications meant manually carrying instructions, paths, hashes and results. We wanted the receiving agent to discover its assignment and the sending agent to discover the result through the same interface.

## What happened

1. Codex sent a scoped code-review and mock-test assignment through MCP.
2. Antigravity discovered the assignment in its inbox and received a verified PMP package.
3. It reported a local review, ten passing Node tests, eight passing Vitest tests and a successful typecheck, without making additional code changes.
4. It sent a linked result package back through MCP and completed the task.
5. Codex discovered the result in its own inbox, received it, independently checked package/file/receipt hashes and completed the result.

The user still started agent turns. No background agent or automatic wake-up was involved. A progress summary was also shared manually in the conversation, but Codex discovered the return through the inbox rather than using identifiers from that summary to route it.

## How it works

Both applications connect to a local `stdio` MCP server with fixed operational profiles. A shared SQLite mailbox tracks task/result relationships, reservations and events. Project context remains in PMP documents; packages and reception receipts remain separate immutable artifacts.

Five mailbox tools extend the previous six local adapter tools:

- `pmp_open_transfer`: create a separate draft workspace.
- `pmp_send_transfer`: prepare, verify and publish a scoped delivery.
- `pmp_inbox`: discover pending work and results.
- `pmp_accept_transfer`: claim, verify, copy and receive a delivery.
- `pmp_report_transfer`: record completion or a blocker.

A task has one recipient and an explicit scope. A result points back to its task and does not automatically start another task. The operator configures permitted roots and scope; package contents cannot expand that policy. Profiles are declared labels, not authenticated agent identities.

The adapter uses the existing [PMP Handoff Bridge](https://github.com/Mad-Max8063/pmp-handoff-bridge) at revision `04f04711dfc10edbf9e77bb98dd390ab03bea60c`. This mailbox work is a separate local extension. The published Hermes plugin and its pinned runtime were left unchanged by the implementation.

## Evidence and lessons

The task and result both reached `COMPLETED`. Package integrity and workspace matching passed in both directions. The result contained six selected files. A later read-only artifact audit checked 52 files across packages, receipts, runtime and implementation evidence. The local implementation suites passed 22 tests, including concurrency, wrong recipients, drift, corruption and interrupted-write recovery.

Real failures shaped the implementation. We encountered changed source files, stale canonical memory placed under a subfolder, unauthorized return workspaces and an invalid draft generated by Codex. These were recorded and corrected while preserving earlier artifacts. Canonical-memory validation now runs before reserving a project, and an explicit recovery path preserves the failed attempt.

One source file remained excluded by the secret scanner. Its local path and digest were recorded privately; its contents were not exported. No customer code, workspaces, credentials, host configuration or raw mailbox database are included in this public update.

The accompanying `PUBLIC-EVIDENCE.json` contains selected hashes and final states from the private case. It is an unsigned, sanitized summary, not the original packages or a standalone reproduction kit. Public readers cannot independently reproduce the private project from these materials.

## What this establishes

This is one observed cross-application workflow on one PC: task publication, recipient discovery, scoped continuation, return publication and sender reception through MCP. The model sessions used their normal quotas. The local server itself made no inference calls; total inference cost was not measured.

The project tests are reported by Antigravity, not independently rerun by Codex in this case. No claim is made about semantic understanding, agent identity, universal reliability, production readiness, quantified token/time savings or autonomous background operation.

The result is a concrete step toward portable project continuity: changing the agent application without making the user carry the handoff details. Next we want to repeat this with another explicitly scoped task and measure intervention, failures and effort.
